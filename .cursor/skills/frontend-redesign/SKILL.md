# Frontend Redesign (Existing Project)

1. Прочитай проект, `DESIGN.md`, файлы инструкций и текущий Git status. Если DESIGN.md не утверждён — остановись и отправь пользователя к анализу.
2. Дай карту изменений: файлы, компоненты, риски, зависимости, этапы. Дождись согласия до массовых правок.
3. Проверь, какой фреймворк и UI-стек уже используются. Не переносить приложение в другой стек. Не добавлять библиотеки без согласования.
4. Внедряй в порядке: дизайн-токены → типографика → hero → галерея проектов → контрастная narrative-секция → остальные секции → интерактивные состояния.
5. Если доступен upstream `frontend-design`, можно использовать его как дополнительный источник, но правила `DESIGN.md` и сохранение проекта приоритетнее.
6. После каждого этапа просматривай diff, убеждайся, что не потеряны ссылки, тексты, формы, ID, SEO-теги, интеграции, маршруты, уже рабочие анимации.
7. Не изменяй пользовательские данные, бизнес-логику, аналитику, оплату, отправку форм. Не делай деплой/публикацию без явного подтверждения.
8. Запускай существующие команды проверки (`package.json`, README). Если их нет — не выдумывай успешный билд.
9. Передай в `responsive-audit` и отчитайся: какие файлы изменены, что проверено, какие остаются риски.
