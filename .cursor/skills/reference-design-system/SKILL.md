# Reference Design System

## Назначение
Преобразовать картинки, скриншоты и описания видео из `design/references/` в собственную дизайн-систему текущего проекта. Если папка отсутствует, проверь `public/references/`, но предупреди, что public может быть доступна на опубликованном сайте.

## Алгоритм
1. До изменений изучи структуру проекта, CSS, компоненты, уже подключённые шрифты, доступные инструменты и существующие правила. Проверь статус Git, предложи сохранить контрольную точку; не запускай разрушительные команды.
2. Перечисли найденные референсы и укажи, какие изображения/видео действительно удалось просмотреть. Если не можешь проанализировать видео, попроси ключевые кадры и таймкоды; не фантазируй о движении.
3. Раздели **наблюдаемое** (крупный sans, смешение italic, асимметрия, галерея) и **оценочное** (названия шрифтов, HEX, скорости анимаций). Пиксельная точность не требуется.
4. Предложи два НЕпохожих друг на друга направления, оба подходящие бренду проекта: смысл, 5–8 цветов по ролям, две пары кириллических шрифтов, шкала заголовков, сетка, отступы, кнопки и карточки, motion и мобильное поведение.
5. Для шрифтов проверь наличие кириллицы, лицензию и подходящие начертания; если проверить невозможно, обозначь это и добавь проверку перед внедрением.
6. Попроси выбрать направление и ДО утверждения не меняй код.
7. После согласования создай в корне `DESIGN.md`: визуальная идея, semantic color tokens, шрифты и fallback, scale, layout/grid, components/states, motion, accessibility, mobile adaptations, запреты и acceptance criteria.
8. Сделай список предполагаемых изменений файлов; передай реализацию в `frontend-redesign`.

## Ограничения
- Не копировать логотипы, фото, тексты, графику и уникальные бренд-активы референса.
- Не выдавать предположения за найденные исходные шрифты и HEX.
- Не менять тексты, ссылки, функции, SEO, маршруты или стек без разрешения.
- Не переносить приватные изображения в public на публикацию.

## Формат ответа до утверждения
Текущий сайт → список изученных референсов → наблюдения и ограничения → концепция A → концепция B → рекомендация → вопрос выбора. Никаких изменений UI кода.
